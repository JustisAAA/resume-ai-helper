# PRD - 简历面试AI助手企业端功能

**文档版本**: v1.0  
**创建日期**: 2026-06-05  
**产品经理**: 许清楚  
**项目**: 简历面试AI助手 - 企业端MVP

---

## 一、产品目标

企业端旨在为招聘企业提供一个智能化的招聘管理平台，通过AI技术帮助企业高效发布职位、筛选候选人，并提升招聘效率和质量。核心价值是**连接企业与求职者，通过AI驱动的简历分析和面试评估，实现精准人岗匹配**。

---

## 二、用户故事

### 核心场景（MVP阶段）

| 角色 | 需求 | 价值 |
|------|------|------|
| **企业招聘人员** | 作为企业用户，我希望能够注册企业账号并登录系统，以便使用企业端功能 | 获得企业身份认证的入口 |
| **企业招聘人员** | 作为企业用户，我希望能够创建和发布招聘职位，以便吸引合适的候选人应聘 | 实现职位信息的对外展示和候选人引流 |
| **企业招聘人员** | 作为企业用户，我希望能够查看申请我发布职位的候选人简历，以便评估其匹配度 | 快速筛选合适的候选人 |
| **企业招聘人员** | 作为企业用户，我希望能够向候选人发送AI面试邀请，以便自动化初步评估 | 减少人工初筛成本，提高效率 |

## 三、需求池

### P0 - 必须有（MVP核心功能）

#### 1. 企业用户注册/登录

**功能描述**：
- 企业用户可以通过邮箱注册账号
- 注册时需要填写企业基本信息（企业名称、统一社会信用代码、联系人、联系电话）
- 支持邮箱验证激活账号
- 登录支持邮箱+密码方式
- 忘记密码可通过邮箱重置

**验收标准**：
- [ ] 企业注册表单包含必填字段验证
- [ ] 邮箱唯一性校验（不能与个人用户重复）
- [ ] 注册成功后发送验证邮件
- [ ] 登录失败有明确错误提示
- [ ] 登录状态保持（Token机制）

**技术要点**：
- 数据库新增 `Enterprise` 表
- User表增加 `Role.ENTERPRISE` 枚举值
- 认证中间件支持企业角色

---

#### 2. 企业发布职位

**功能描述**：
- 企业登录后可在"职位管理"页面发布新职位
- 职位信息包含：职位名称、部门、工作地点、薪资范围、职位描述、任职要求、招聘人数、截止日期
- 职位状态：草稿、已发布、已下架
- 支持职位的编辑、下架、删除操作

**验收标准**：
- [ ] 发布职位表单有完整的字段验证
- [ ] 职位发布后状态为"已发布"，在前端职位列表可见
- [ ] 草稿状态的职位不会对外展示
- [ ] 已发布的职位可以下架（状态变为"已下架"）
- [ ] 只有职位创建企业可以编辑/删除该职位

**技术要点**：
- 数据库新增 `Job` 表
- Job表关联 Enterprise ID
- 实现职位CRUD API

---

### P1 - 应该有（提升体验）

#### 3. 简历查看与管理

**功能描述**：
- 企业可以查看申请对应职位的候选人简历
- 简历以解析后的结构化数据展示（基本信息、教育背景、工作经历、技能）
- 支持简历搜索和筛选（按关键词、学历、工作经验等）
- 可以标记简历状态（待筛选、已通过、已拒绝）

**验收标准**：
- [ ] 简历列表按申请时间倒序排列
- [ ] 点击简历可查看详细解析内容
- [ ] 支持按候选人姓名/关键词搜索
- [ ] 可以批量更新简历状态

---

#### 4. AI面试邀请

**功能描述**：
- 企业可以向候选人发送AI面试邀请
- 系统自动生成面试链接发送给候选人邮箱
- 企业可以查看候选人的面试进度和报告
- 面试报告包含：总分、各维度评分、改进建议

**验收标准**：
- [ ] 选择候选人后点击"发送面试邀请"
- [ ] 系统自动发送包含面试链接的邮件
- [ ] 企业端可实时查看面试状态（未开始/进行中/已完成）
- [ ] 面试完成后企业可查看完整报告

---

### P2 - 可以有（未来规划）

#### 5. 企业品牌页

**功能描述**：
- 企业可以定制品牌展示页面（Logo、公司简介、企业文化、福利）
- 公开访问，用于雇主品牌建设
- 展示该企业所有在招职位

---

#### 6. 批量操作

**功能描述**：
- 批量发送面试邀请
- 批量更新简历状态
- 批量下架职位
- 导出简历数据（Excel）

## 五、待确认问题

### 5.1 企业认证机制

**问题**：企业注册后是否需要审核认证？还是注册即可使用？

**选项**：
- A. 注册后直接可用（快速启动，但可能有虚假企业）✅ **已确认**
- B. 需要管理员审核通过后才能发布职位（更安全，但增加运营成本）

**决策**：MVP阶段采用方案A，注册后直接可用，后续增加审核机制

---

### 5.2 职位发布限制

**问题**：是否限制企业可发布的职位数？

**选项**：
- A. 不限制（自由发布）✅ **已确认**
- B. 限制免费企业最多5个在招职位
- C. 按套餐限制

**决策**：MVP阶段采用方案A，不限制，后续引入套餐计费

---

### 5.3 简历数据隔离

**问题**：企业A能否看到企业B收到的简历？

**选项**：
- A. 严格隔离（每个企业只能看到自己职位的简历）✅ **已确认**
- B. 付费后可查看其他企业的简历（涉及隐私，不推荐）

**决策**：采用方案A，在数据库层面做权限控制

---

### 5.4 面试邀请方式

**问题**：面试邀请是通过系统内置邮件发送，还是生成链接由企业自行发送？

**选项**：
- A. 系统自动发送邮件（体验好，但需要配置邮件服务）
- B. 生成面试链接，企业复制后自行发送（灵活，但增加企业操作成本）✅ **已确认**

**决策**：MVP阶段采用方案B（快速实现），后续增加方案A

---

### 5.5 数据库设计

**问题**：Enterprise表是独立表还是继承自User表？

**选项**：
- A. 独立Enterprise表，通过userId关联User表（清晰，但查询稍复杂）✅ **已确认**
- B. User表增加企业字段（简单，但不规范）

**决策**：采用方案A，符合数据库范式

## 六、技术实现建议

### 6.1 数据库模型（Prisma Schema）

```prisma
model Enterprise {
  id            String   @id @default(cuid())
  name          String   // 企业名称
  creditCode    String   @unique // 统一社会信用代码
  contactPerson String   // 联系人
  contactPhone  String   // 联系电话
  email         String   @unique // 登录邮箱
  password      String   // 加密密码
  verified      Boolean  @default(false) // 是否认证
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  
  jobs          Job[]    // 发布的职位
  user          User?    @relation(fields: [userId], references: [id])
  userId        String?  @unique
  
  @@map("enterprises")
}

model Job {
  id              String   @id @default(cuid())
  title           String   // 职位名称
  department      String?  // 部门
  location        String?  // 工作地点
  salaryMin       Int?     // 最低薪资(K)
  salaryMax       Int?     // 最高薪资(K)
  description     String   // 职位描述
  requirements    String   // 任职要求
  headcount       Int      @default(1) // 招聘人数
  deadline        DateTime? // 截止日期
  status          JobStatus @default(DRAFT) // 草稿/已发布/已下架
  enterpriseId    String   // 发布企业ID
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
  
  enterprise     Enterprise @relation(fields: [enterpriseId], references: [id])
  applications   Application[] // 职位申请
  
  @@map("jobs")
}

enum JobStatus {
  DRAFT     // 草稿
  PUBLISHED // 已发布
  CLOSED    // 已下架
}

model Application {
  id          String   @id @default(cuid())
  jobId       String   // 申请的职位ID
  candidateId String   // 候选人ID
  resumeId    String   // 简历ID
  status      AppStatus @default(PENDING) // 待筛选/已通过/已拒绝
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  
  job         Job      @relation(fields: [jobId], references: [id])
  candidate   User     @relation(fields: [candidateId], references: [id])
  resume      Resume   @relation(fields: [resumeId], references: [id])
  
  @@unique([jobId, candidateId]) // 同一职位不能重复申请
  @@map("applications")
}

enum AppStatus {
  PENDING    // 待筛选
  APPROVED   // 已通过
  REJECTED   // 已拒绝
}
```

### 6.2 API端点设计

**企业认证**：
- `POST /api/enterprise/register` - 企业注册
- `POST /api/enterprise/login` - 企业登录
- `POST /api/enterprise/verify-email` - 邮箱验证

**职位管理**：
- `POST /api/jobs` - 创建职位
- `GET /api/jobs` - 获取职位列表（企业自己的）
- `GET /api/jobs/:id` - 获取职位详情
- `PUT /api/jobs/:id` - 更新职位
- `DELETE /api/jobs/:id` - 删除职位
- `PATCH /api/jobs/:id/publish` - 发布职位
- `PATCH /api/jobs/:id/close` - 下架职位

**简历管理**：
- `GET /api/jobs/:jobId/applications` - 查看职位的简历申请
- `PATCH /api/applications/:id/status` - 更新简历状态
