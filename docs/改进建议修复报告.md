## SUG-001：前端构建产物较大（2.3MB），建议代码分割优化

### 问题描述
前端构建后的bundle太大（2.3MB），影响加载速度。原因是所有页面组件都直接导入，打包成一个文件。

### 修复方案
使用 `React.lazy()` 和 `Suspense` 实现路由级别的代码分割：
1. 将所有页面组件改为懒加载导入
2. 用 `Suspense` 组件包裹 `Routes`
3. 提供加载状态 fallback

### 修改文件
- `frontend/src/App.tsx`（第1-31行，第77-124行）

### 验证结果
✅ **构建成功**
- 命令：`cd frontend && npm run build`
- 结果：生成多个小chunk，不再是单一大文件
- 最大chunk：`exportPdf-DIZMEqvq.js` (777KB)
- 警告：仍有超过500KB的chunk（可后续优化）

### 构建产物分析
| 文件 | 大小 | gzip大小 |
|------|------|----------|
| exportPdf-DIZMEqvq.js | 777.45 kB | 236.19 kB |
| InterviewReport-CG96QdZb.js | 444.86 kB | 143.43 kB |
| CategoricalChart-CXyBZ03F.js | 260.89 kB | 83.59 kB |
| html2canvas.esm-B4goYG9Y.js | 201.54 kB | 48.11 kB |
| index.es-1Ob5d0ZP.js | 150.84 kB | 51.63 kB |

**结论**：代码分割已生效，加载性能提升。

## SUG-002：API返回中文在终端显示乱码，建议统一编码格式

### 问题描述
后端API返回的中文在终端显示乱码（Windows环境）。原因是Windows终端默认编码可能是GBK，不是UTF-8。

### 修复方案
修改 `backend/package.json` 的 `dev` 脚本，在前面添加 `chcp 65001 >nul &&`（Windows切换UTF-8编码）。

### 修改文件
- `backend/package.json`（第10行）

### 修改内容
```json
// 修改前
"dev": "node scripts/kill-port.js 3002 && npx ts-node-dev --respawn --transpile-only src/index.ts"

// 修改后
"dev": "chcp 65001 >nul && node scripts/kill-port.js 3002 && npx ts-node-dev --respawn --transpile-only src/index.ts"
```

### 验证结果
✅ **TypeScript检查通过**
- 命令：`cd backend && npx tsc --noEmit`
- 结果：无错误

⚠️ **待验证**：需要启动后端服务，调用API，观察终端中文显示是否正常。

## SUG-003：缺少详细的参数校验错误信息，建议优化错误提示

### 问题描述
API参数校验失败时，返回的错误信息不够详细（比如只返回"参数错误"，不告诉哪个字段错了）。

### 修复方案
在后端路由中添加参数校验逻辑，返回详细的错误信息：
- 格式：`{ error: "参数校验失败", details: [{ field: "email", message: "邮箱格式不正确" }] }`
- 统一错误响应格式

### 修改文件
- `backend/src/routes/enterprise.ts`（第8-54行，第56-71行）
- `backend/src/routes/job.ts`（第8-41行，第147-152行）

### 修改内容

#### 1. enterprise.ts - POST /register（企业注册）
添加校验：
- `email`：必填，格式验证
- `password`：必填，最少6位
- `name`：必填

错误信息示例：
```json
{
  "error": "参数校验失败",
  "details": [
    { "field": "email", "message": "邮箱格式不正确" },
    { "field": "password", "message": "密码长度不能少于6位" }
  ]
}
```

#### 2. enterprise.ts - POST /login（企业登录）
添加校验：
- `email`：必填
- `password`：必填

#### 3. job.ts - POST /（创建职位）
添加校验：
- `title`：必填
- `description`：必填

#### 4. job.ts - PATCH /:id/status（更新职位状态）
改进错误信息：
- 修改前：`{ "error": "无效的状态值" }`
- 修改后：`{ "error": "参数校验失败", "details": [{ "field": "status", "message": "状态值无效，必须是 ACTIVE、CLOSED 或 DRAFT" }] }`

### 验证结果
✅ **TypeScript检查通过**
- 命令：`cd backend && npx tsc --noEmit`
- 结果：无错误

⚠️ **待验证**：需要使用curl或Postman测试API，传入错误参数，检查错误信息是否详细。
