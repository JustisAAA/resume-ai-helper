## 1. 技术债务概述

### 1.1 什么是技术债务？

**定义**：
> 技术债务是指由于选择快速但不完善的解决方案，而导致未来需要额外工作来修复的情况。就像金融债务一样，技术债务也会产生"利息"（维护成本、bug风险、开发效率降低）。

**本项目的债务来源**：
1. **时间压力**：为赶大赛deadline，选择快速实现方案
2. **经验不足**：初期架构设计考虑不周
3. **需求变更**：功能需求中途变更，导致代码重构不及时
4. **技术选型**：某些技术选型后期发现不合适

### 1.2 债务分类

| 债务类型 | 数量 | 总利息（负面影响） | 总偿还成本 |
|---------|------|----------------|------------|
| **安全债务** | 3项 | 高（安全风险） | 低（5人天） |
| **性能债务** | 4项 | 中（用户体验差） | 中（12人天） |
| **代码质量债务** | 5项 | 中（维护成本高） | 高（20人天） |
| **架构债务** | 2项 | 低（扩展性差） | 高（30人天） |
| **测试债务** | 1项 | 高（bug风险） | 中（15人天） |

## 2. 债务清单

### 2.1 安全债务（🔴 高优先级）

#### 债务#1：JWT存储在localStorage

**位置**：`frontend/src/services/api.ts` + 所有API调用处

**债务描述**：
```typescript
// 当前实现：Token存储在localStorage（可被XSS攻击读取）
const token = localStorage.getItem('token');
axios.defaults.headers.common['Authorization'] = `Bearer ${token}`;
```

**利息（负面影响）**：
- **XSS攻击风险**：恶意脚本可读取localStorage中的token
- **CSRF防护缺失**：Cookie自动发送，需额外CSRF token防护
- **合规问题**：等保2.0等安全标准要求HttpOnly Cookie

**偿还方案**：
```
方案：改用HttpOnly Cookie
1. 后端登录接口返回Set-Cookie头
2. 前端使用credentials: 'include'发送请求
3. 移除localStorage操作
成本：3人天
风险：低（标准做法）
```

**优先级**：🔴 P0（立即偿还）

---

#### 债务#2：文件上传仅检查扩展名

**位置**：`backend/src/controllers/resumeController.ts` (upload函数)

**债务描述**：
```typescript
// 当前实现：只检查文件扩展名
const fileExt = path.extname(file.originalname).toLowerCase();
if (!['.pdf', '.docx'].includes(fileExt)) {
  return res.status(400).json({ error: '仅支持PDF和DOCX' });
}
```

**利息（负面影响）**：
- **恶意文件上传**：攻击者可上传.php/.exe等文件（改扩展名）
- **解析失败**：文件内容与扩展名不符，导致解析错误
- **存储浪费**：垃圾文件占用磁盘空间

**偿还方案**：
```
方案：添加MIME类型验证 + 文件头验证
1. 使用file.mimetype验证
2. 使用magic number验证文件头
3. 添加文件大小限制（后端强制）
成本：2人天
风险：低
```

**优先级**：🔴 P0（立即偿还）

#### 债务#3：无Rate Limiting

**位置**：`backend/src/index.ts` (应用入口)

**债务描述**：
```typescript
// 当前实现：无请求频率限制
app.use(express.json());
app.use('/api', routes);
// 缺少：rateLimit中间件
```

**利息（负面影响）**：
- **API滥用**：攻击者可无限调用API（如暴力破解密码）
- **资源耗尽**：大量请求导致服务器崩溃
- **成本失控**：AI API调用无限制，费用暴涨

**偿还方案**：
```
方案：添加express-rate-limit中间件
1. 全局限制：100请求/15分钟/IP
2. 认证API限制：5请求/分钟/IP
3. AI API限制：10调用/小时/用户
成本：1人天
风险：低
```

**优先级**：🟡 P1（本周偿还）

### 2.2 性能债务（🟡 中优先级）

#### 债务#4：面试列表无分页

**位置**：`frontend/src/pages/InterviewList.tsx`

**债务描述**：
```typescript
// 当前实现：前端过滤，一次性加载所有面试
const [interviews, setInterviews] = useState([]);
useEffect(() => {
  interviewAPI.list(token).then(res => {
    setInterviews(res.data.interviews); // 所有数据！
  });
}, []);
```

**利息（负面影响）**：
- **加载慢**：用户有100+面试时，加载时间>5秒
- **内存占用高**：前端存储所有数据
- **滚动卡顿**：长列表渲染性能差

**偿还方案**：
```
方案：后端添加分页支持
1. 后端：GET /api/interviews?page=1&pageSize=10
2. 前端：添加分页控件（上一页/下一页/页码）
3. 添加缓存：已加载页缓存到前端
成本：3人天
风险：低
```

**优先级**：🟡 P1（本周偿还）

#### 债务#5：简历解析无队列

**位置**：`backend/src/controllers/resumeController.ts` (upload函数)

**债务描述**：
```typescript
// 当前实现：上传后立即解析（同步）
const data = await pdfParse(filePath); // 可能耗时10+秒
content = data.text;
// 用户需要等待解析完成才能继续
```

**利息（负面影响）**：
- **超时风险**：大文件解析超过30秒，导致API超时
- **用户体验差**：上传后卡在"解析中"状态
- **服务器压力大**：解析占用主线程

**偿还方案**：
```
方案：使用消息队列异步解析
1. 上传后立即返回"解析中"状态
2. 将解析任务推送到Redis队列
3. Worker进程异步处理，完成后更新数据库
4. 前端轮询或使用WebSocket通知完成
成本：5人天
风险：中（引入新组件Redis+Worker）
```

**优先级**：🟢 P2（本月偿还）

3. 提取MessageList组件（消息列表）

## 6. 预防措施

### 6.1 如何避免新债务？

#### 措施1：代码审查（Code Review）

**规则**：
- 所有代码合并前必须经过至少1人Review
- Review检查清单：
  - [ ] 是否有安全风险？（XSS、SQL注入、文件上传等）
  - [ ] 是否有性能问题？（N+1查询、大循环、无分页等）
  - [ ] 是否有代码质量问题？（重复代码、过长函数、缺少测试等）
  - [ ] 是否引入了技术债务？如果有，是否记录了债务登记？

---

#### 措施2：技术债务登记

**规则**：
- 每次代码提交，如果引入了技术债务，必须在`docs/technical-debt.md`中登记
- 登记格式：
  ```
  #### 债务#[ID]：简短描述
  
  **位置**：文件路径 + 行号
  **原因**：为什么选择快速方案而非完善方案
  **利息**：不偿还会有什么后果
  **偿还方案**：如何偿还
  **预计成本**：X人天
  **登记人**：姓名 + 日期
  ```

---

#### 措施3：定期债务审查会议

**频率**：每2周1次，1小时

**议程**：
1. 回顾过去2周新增的债务（如果有）
2. 评估现有债务的利息变化（是否在"利滚利"？）
3. 决定是否偿还某个债务（基于优先级矩阵）
4. 分配偿还任务（谁、何时完成）
