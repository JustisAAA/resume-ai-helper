## 1. 引言

### 1.1 编写目的

本文档旨在全面描述"简历面试AI助手"系统的整体设计与实现方案，为系统的开发、测试、部署及后续维护提供完整的参考依据。本文档面向开发者、测试人员、评审专家及项目维护者。

### 1.2 项目背景

随着高校毕业生就业竞争日益激烈，传统简历筛选和面试评估方式存在效率低下、标准不统一、反馈不及时等痛点。本系统利用大语言模型技术，构建一个集简历分析、模拟面试、智能评估、职位匹配于一体的AI求职辅助平台，同时为企业和HR提供高效的招聘管理工具。

本项目为山东省大学生软件设计大赛参赛作品。

### 1.3 项目目标

| 目标 | 说明 |
|------|------|
| 求职者端 | 提供AI简历评分与优化、模拟面试、人岗匹配、求职指导等全流程辅助功能 |
| 企业端 | 提供职位发布、AI简历筛选、企业面试评估、招聘数据分析等功能 |
| HR端 | 提供岗位级简历筛选、面试管理、求职者沟通等精细化操作权限 |
| 管理员端 | 提供用户管理、举报审核、信用分管理、平台数据统计等功能 |

## 2. 系统总体设计

### 2.1 系统定位

本系统是一个面向求职者、企业HR、管理员三类用户的Web端在线平台，以AI大语言模型为核心驱动，提供从简历制作到面试通过的全链路智能辅助。

### 2.3 系统分层设计

| 层 | 技术选型 | 职责 | 关键约束 |
|----|---------|------|---------|
| **表现层（前端）** | React 18 + TypeScript + Vite 6 | UI渲染、用户交互、路由管理、API调用 | 端口5173；无直接数据库访问 |
| **样式层** | Tailwind CSS 3.4 + brand-* 主题变量 | 界面样式、响应式布局、主题切换 | CSS变量驱动三套角色主题 |
| **应用层（后端）** | Express 4.21 + TypeScript 5.3 | 业务逻辑、数据验证、AI代理、权限控制 | 端口3002；无状态JWT设计 |
| **数据访问层** | Prisma 6.2+ ORM | 数据持久化、关系管理、迁移管理 | 支持SQLite；事务保护 |
| **数据层** | SQLite | 数据存储 | 内置，无需额外安装 |
| **AI服务层** | 腾讯元器API v2.0 | 简历分析、面试问答、工具调用 | 双智能体（求职者/企业） |

### 2.5 关键技术决策

| 决策项 | 选择方案 | 理由 |
|--------|---------|------|
| 前端框架 | React + TypeScript | 类型安全、社区成熟、组件化开发 |
| 构建工具 | Vite | 极速HMR、原生ESM支持 |
| 样式方案 | Tailwind CSS + CSS变量 | 原子化样式、运行时主题切换 |
| 后端框架 | Express | 轻量灵活、中间件生态丰富 |
| ORM框架 | Prisma | 类型安全的查询、自动迁移、关系管理 |
| 数据库 | SQLite | 无需服务端安装、适合比赛演示 |
| 认证方式 | JWT（双Token体系） | 无状态、前后端分离友好 |
| AI接口 | 腾讯元器API | 双智能体支持、API兼容性好 |
| 密码加密 | bcryptjs | 安全性高、salt自动管理 |
| 代码规范 | TypeScript严格模式 | 在编译期捕获类型错误 |

## 3. 功能详细设计

### 3.1 求职者端功能

#### 3.1.1 简历管理

| 功能 | 子功能 | 说明 |
|------|--------|------|
| 简历上传 | PDF/Word上传 | 支持PDF和Word格式，AI自动解析内容 |
| 简历列表 | 查看/筛选/删除 | 按状态（草稿/已分析/已归档）筛选 |
| 简历详情 | 查看分析结果 | 显示AI评分、能力画像、改进建议 |
| 简历评分 | 多维度评分 | AI对简历进行结构/内容/匹配度评分 |
| 简历优化 | AI改写建议 | AI逐段分析并给出优化建议 |

#### 3.1.2 面试模拟

| 功能 | 子功能 | 说明 |
|------|--------|------|
| 创建面试 | 配置难度/语言/AI角色 | 支持EASY/MEDIUM/HARD三级难度 |
| 自由练习面试 | AI实时问答 | 多轮对话，AI评估+下一题 |
| 企业面试 | 候选人不看评分 | 仅展示问题，评估结果对企业端可见 |
| 面试报告 | 多维度评估 | 评分、反馈、逐题分析 |
| 面试历史 | 列表/筛选 | 按类型（练习/企业）和状态筛选 |

#### 3.1.3 职位搜索与申请

| 功能 | 说明 |
|------|------|
| 职位广场 | 公开浏览全部Active职位，带关键词搜索和分页 |
| 职位详情 | 查看职位描述、要求、薪资范围、图片轮播、HR信息 |
| 提交申请 | 选择简历+求职信，AI自动生成简历分析 |
| 申请管理 | 查看申请状态（待审核/审核中/已通过/已拒绝） |

#### 3.1.4 AI工具（5个独立工具）

| 工具 | 功能 | 输入 | 输出 |
|------|------|------|------|
| 简历评分 | 多维度AI评分 | 简历文本 | 5维度评分+文字评语 |
| 人岗匹配 | 匹配度分析 | 简历+岗位描述 | 匹配百分比+差距分析+提升建议 |
| 简历优化 | 智能改进建议 | 简历文本+优化方向 | 逐段优化建议+修改示例 |
| AI出题 | 面试题预测 | 岗位描述+简历 | 高频面试题+标准答案要点 |
| 求职指导 | 全阶段建议 | 用户描述的问题 | 针对性求职建议 |

#### 3.1.5 其他功能

| 功能 | 说明 |
|------|------|
| 聊天沟通 | 与负责HR一对一消息沟通（HTTP轮询3秒） |
| 报告中心 | 汇总所有面试报告、分析报告 |
| 简历模板 | 5套专业模板，一键套用导出 |

## 4. 数据库设计

### 4.1 数据库选型

采用 **SQLite** 作为数据库引擎。SQLite无需安装独立的数据库服务，数据文件直接存储在项目目录中，适合比赛演示环境。使用 **Prisma ORM** 进行数据库访问和迁移管理。

- 数据库文件：`backend/prisma/dev.db`
- ORM配置文件：`backend/prisma/schema.prisma`
- 迁移记录：`backend/prisma/migrations/`

### 4.3 表结构设计

#### 4.3.1 users（用户表）

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|---------|------|------|
| id | String (UUID) | PK | 主键 |
| email | String | UNIQUE, NOT NULL | 邮箱（登录凭证） |
| password_hash | String | NOT NULL | 密码哈希（bcryptjs） |
| name | String | NULL | 显示名称 |
| avatar | String | NULL | 头像URL |
| role | Enum(USER/HR/ENTERPRISE/ADMIN) | DEFAULT 'USER' | 用户角色 |

## 7. 系统安全设计

### 7.1 认证安全

| 措施 | 实现方式 | 说明 |
|------|---------|------|
| 密码加密 | bcryptjs (salt rounds=10) | 即使数据库泄露也无法还原密码 |
| 密码策略 | ≥8位，包含大写+小写+数字 | 注册/修改密码时校验 |
| JWT认证 | jsonwebtoken（7天过期） | 无状态认证，适合分布式部署 |
| 双Token体系 | token + hrToken | User/HR分离认证互不干扰 |
| 登录限流 | express-rate-limit | 同一IP限制请求频率 |

### 7.2 权限控制

| 控制层 | 实现 | 说明 |
|--------|------|------|
| 前端路由守卫 | 5个守卫组件 | 未登录→重定向，角色错误→跳转 |
| 后端中间件 | 4个权限中间件 | authenticateToken / requireAdmin / requireEnterprise / requireEnterpriseOrHR |
| HR岗位级隔离 | HRAccount.jobId过滤 | HR只能操作绑定岗位的数据 |
| 企业主和HR分离 | Dashboard按钮条件渲染 | ENTERPRISE角色不显示操作按钮 |
| 消息权限 | 代码级校验 | 禁止USER↔ENTERPRISE直接通信 |

### 7.3 数据安全

| 措施 | 说明 |
|------|------|
| 级联删除 | Prisma onDelete: Cascade，删除用户/企业时自动清理关联数据 |
| 日志脱敏 | sanitizeError工具（63处使用），避免密码/Token泄露到日志 |
| 文件上传限制 | 类型白名单（JPG/PNG/PDF）、大小限制（≤5MB或≤10MB） |
| 信用分系统 | 初始100分，违规扣分，≤0封禁，形成管理闭环 |
| SQL注入防护 | Prisma ORM自动参数化查询 |

### 7.4 HTTP安全

| 措施 | 实现 |
|------|------|
| 安全头 | helmet中间件 |
| CORS | 跨域访问控制 |
| 限流 | express-rate-limit（60req/min） |
| 错误响应 | 全局错误中间件统一格式，不暴露堆栈信息 |

### 7.5 前端安全

| 措施 | 说明 |
|------|------|
| Error Boundary | 全局包裹，任一组件崩溃不导致白屏 |
| 类型安全 | TypeScript严格模式，编译期捕获类型错误 |
| FOUC防护 | index.html同步脚本提前设置dark class |
| Toast替代alert | 14个文件30+处替换，避免阻塞式弹窗 |
