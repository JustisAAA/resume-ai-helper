## 1. 项目概述

### 1.1 项目定位

简历面试AI助手是一个基于AI的在线求职招聘平台，为**求职者**提供简历分析、AI模拟面试、职位搜索等功能，为**企业**提供职位发布、简历筛选、AI面试评估等功能，为**HR**提供岗位级数据操作权限。

### 1.2 核心价值

| 角色 | 核心需求 | 解决方案 |
|------|---------|---------|
| 求职者 | 提升求职竞争力 | AI简历评分/优化、模拟面试、多维度评估报告 |
| 企业/HR | 高效筛选候选人 | 职位发布、AI简历分析、企业AI面试、数据统计 |
| 管理员 | 平台治理 | 用户管理、举报审核、信用分管理 |

### 1.3 技术栈

| 层 | 技术 | 版本 |
|----|------|------|
| 前端 | React + TypeScript + Vite | React 18, TS 5.6, Vite 6 |
| 样式 | Tailwind CSS（含品牌色变量） | 3.4 |
| 路由 | React Router DOM | 7.1 |
| 图表 | Recharts | 2.15 |
| 后端 | Express + TypeScript | Express 4.21, TS 5.3 |
| ORM | Prisma | 6.2+ |
| 数据库 | SQLite | 内置，无需额外安装 |
| AI | 腾讯元器 API | v2.0（双智能体） |
| 认证 | JWT | jsonwebtoken 9.0 |
| 密码加密 | bcryptjs | salt rounds=10 |

### 3.2 路由守卫

| 守卫 | 条件 | 行为 |
|------|------|------|
| `GuestRoute` | 已登录 | → 根据角色跳转 |
| `UserRoute` | role=USER | ADMIN→/admin, ENTERPRISE→/enterprise/dashboard |
| `AdminRoute` | role=ADMIN | 否则→/login |
| `EnterpriseRoute` | role=ENTERPRISE | 否则→/enterprise/login |
| `HRRoute` | hrToken存在 | 否则→/hr/login |

```css
:root[data-role="enterprise"] { --brand-500: 139 92  246; } /* Violet */
:root[data-role="hr"]        { --brand-500: 16  185 129; }  /* Emerald */
```

```tsx
// App.tsx - 主题自动切换
useEffect(() => {
  // 根据 localStorage 中的登录信息自动设置 data-role
  // 优先级：HR 登录 > 企业用户 > 普通用户 > 默认求职者
```


### 4.2 API端点设计（完整）

#### 4.2.1 认证模块 `/api/auth`

| 方法 | 路径 | 中间件 | 说明 |
|------|------|--------|------|
| POST | `/register` | - | 用户注册（密码≥8位+大小写+数字） |

### 4.3 中间件架构

```
请求流:
  ┌──────┐    ┌───────┐    ┌─────────┐    ┌────────┐    ┌──────────┐
  │ cors │ → │helmet │ → │rateLimit│ → │  auth  │ → │ resource │
  │      │    │       │    │         │    │(JWT校验)│   │ Handler  │
  └──────┘    └───────┘    └─────────┘    └────────┘    └──────────┘
                                                  │
                                          ┌───────┴────────┐
                                          ▼                ▼
                                    authenticateToken  requireHR
                                    requireAdmin       requireEnterprise
                                    requireEnterpriseOrHR
```

| 中间件 | 职责 |
|--------|------|
| `cors` | 跨域访问控制 |
| `helmet` | HTTP安全头 |
| `express-rate-limit` | API限流（60次/分钟） |
| `authenticateToken` | JWT Token解析 → `req.user!`（全局类型声明） |
| `requireAdmin` | 验证 `req.user.role === 'ADMIN'` |
| `requireEnterprise` | 验证 `req.user.role === 'ENTERPRISE'` |
| `requireEnterpriseOrHR` | 验证 `ENTERPRISE` 或 `HR` |
| `multer` | 文件上传处理（头像/简历/职位图片） |

```
全局错误中间件:

  │ try/catch│    │ 抛出错误   │    │ (index.ts 注册)   │
  └──────────┘    └───────────┘    └──────────────────┘
                                          │

                                    ▼            ▼
                              JSON响应   日志 (sanitizeError 脱敏)
```

## 7. 权限与安全设计

### 7.1 双重认证体系

| 端 | 认证方式 | Token存储 | API前缀 |
|----|---------|----------|---------|
| 求职者/企业主/管理员 | JWT | `localStorage.token` | `/api/*` |
| HR子账号 | JWT | `localStorage.hrToken` | `/api/*` |

> 消息API和举报API的baseURL使用 `getApiUrl('')` 而非 `'/api'`

### 7.2 角色通信权限矩阵

| 发送方 | 接收方 | 允许? | 说明 |
|--------|--------|:----:|------|
| USER | HR | ✅ | 求职者与负责HR沟通 |
| HR | USER | ✅ | HR与求职者沟通 |
| HR | ENTERPRISE | ✅ | HR与HR组长内部沟通 |
| ENTERPRISE | HR | ✅ | HR组长与HR内部沟通 |
| USER | ENTERPRISE | ❌ | 禁止求职者直接联系企业主 |
| ENTERPRISE | USER | ❌ | 企业主不能直接联系求职者 |

### 7.3 HR岗位级权限隔离

```
企业主(ENTERPRISE)                    普通HR(HR)
     │                                    │
     │ 创建子账号                          │ 绑定岗位
     ▼                                    ▼
  ┌─────────────────────────┐    ┌──────────────────────┐
  │ 看到所有岗位的面试       │    │ 仅看到绑定岗位的面试   │
  │ 可为任何岗位发起面试     │    │ 只能为绑定岗位发起面试 │
  │ 有HR账号管理权限         │    │ 无HR账号管理权限       │
  │ 【Dashboard不显示操作按钮】│    │ 【Dashboard显示操作按钮】  │
  └─────────────────────────┘    └──────────────────────┘
```

#### HRDashboard按钮显示逻辑

- `getHRDashboard` 返回 `userRole` 字段（'ENTERPRISE' 或 'HR'）
- `userRole === 'HR'`：显示「简历筛选」和「面试管理」按钮
- `userRole === 'ENTERPRISE'`：隐藏这两个按钮
- 消息按钮：始终显示
- 企业端 Dashboard 同样遵循此原则，仅保留发布/管理/消息/数据四个按钮

### 7.4 安全措施

| 措施 | 实现 |

### D. 关键设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 数据库 | SQLite | 无需额外配置，适合比赛演示 |

| 认证 | 双Token体系 | User/HR分离认证，互不干扰 |
| 分页 | 后端偏移分页+前端Pagination | 平衡实现复杂度和查询效率 |
| 错误处理 | 全局中间件+ErrorBoundary | 前端防白屏，后端响应统一 |
